{% if state == "on" %} {% set url = "https://" ~ domain ~ ("/" if port == 443 else ":" ~ port ~ "/") %}

At home, open {{ url }}: the same Home Assistant over HTTPS, without a client certificate.

  • Your local DNS (router, AdGuard Home, Pi-hole, the Dnsmasq app) must resolve {{ domain }} to the IPv4 address of this Home Assistant host. The address itself (https://192.168.x.y:{{ port }}/) does not work: the certificate is for {{ domain }}.
  • It answers only devices with a private address (local network); every other connection gets "403 Forbidden". {% if lan_rt.lan_refused %}It also refuses {% for addr in lan_rt.lan_refused %}{{ addr }}{% if not loop.last %}, {% endif %}{% endfor %}: Docker's address on the host, which hides where a connection really comes from (IPv6 connections, connections from the host itself) - use IPv4.{% endif %}
  • Never forward host port {{ port }} on your router. From the internet, use https://{{ domain }}/ with a client certificate.
{% else %}

{% if state == "unknown" %}Off: the host port of 4443/tcp could not be read (no Supervisor API), so the add-on does not offer it. {% else %}Off. The add-on can also offer HTTPS for your local network without a client certificate, on a second port that only devices at home can use.{% endif %}

To turn it on:

  1. Open Settings > Apps > Caddy mTLS Proxy > Configuration.
  2. In the Network card, turn on Show disabled ports and enter a free host port for 4443/tcp (for example 9443, or 443 if Home Assistant does not use it).
  3. Select Save and restart the app.
  4. Let your local DNS resolve {{ domain }} to this host's IPv4 address. Never forward that port on your router.
{% endif %}
