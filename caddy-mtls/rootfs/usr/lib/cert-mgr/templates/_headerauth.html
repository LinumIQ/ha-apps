  • Every request that carries this header with exactly the key is accepted{% if ha.mtls %} without a client certificate{% endif %}.
  • The header is removed before Home Assistant sees the request.
    • {% if ha.mtls %}
  • A visitor without a client certificate and without the key gets "403 Forbidden" instead of a failed TLS handshake. A certificate that is presented is still checked as before: a revoked or unknown one ends the connection, also with the key.
  • Forwarding headers follow the same rules as for visitors with a client certificate.
    • {% endif %}
  • While a key is set, the add-on's log lines carry no request headers{% if ha.access_log %}; each line of the access log has a field auth that says how the request was let in or why it was refused{% else %} (with the option access_log on, each line of the access log has a field auth that says how the request was let in or why it was refused){% endif %}.
  • To switch it off, empty header_auth_key in the app's configuration and restart the app.

Clients like a watch app: the app must send the header with every request - requests it makes without it (renewing a token, logging in through the phone's browser) are refused. Give such an app a Home Assistant long-lived access token (your profile, Security tab) instead of a login.

To change the key, enter a new one in the app's configuration and restart the app:
